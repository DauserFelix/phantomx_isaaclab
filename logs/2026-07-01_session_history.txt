4. LOG_STD = 2.0 — KEIN ZEICHEN FÜR NICHT-KONVERGENZ
--------------------------------------------------------------------------------

Erklärung: log_std_parameter ist ein separater gelernter Parameter, unabhängig
vom Netzwerk-Output (mean_actions). Entropy-Koeffizient (0.005) verhindert,
dass log_std kollabiert solange mean_actions gute Rewards liefern.

Während Inferenz: nur mean_actions wird genutzt (deterministisch).
Policy kann exzellent sein trotz log_std = 2.0.

Output-Range [-40, +58] für Zero-Observations war irreführender Test —
Zero-Obs liegt weit außerhalb der Trainingsverteilung. Mit echten normierten
Obs gibt die Policy sinnvolle Werte.

6. IMU GRAVITY-FIX — QUATERNION STATT BESCHLEUNIGUNG
--------------------------------------------------------------------------------

Problem vorher: gravity_b = a_imu / |a_imu| → falsch bei Bewegung + falsches Vorzeichen

Fix (korrekte Quaternion-Rotation R^T @ [0,0,-1]):
  qx,qy,qz,qw = msg.orientation.x/y/z/w (normiert)
  gravity_b[0] = -(2*(qx*qz - qy*qw))
  gravity_b[1] = -(2*(qy*qz + qx*qw))
  gravity_b[2] = -(1 - 2*(qx² + qy²))

Testfälle verifiziert:
  identity quat:    [0, 0, -1]  ✓
  +45° pitch fwd:   [+0.707, 0, -0.707]  ✓
  -45° pitch back:  [-0.707, 0, -0.707]  ✓
  +90° roll rechts: [0, -1, 0]  ✓
  180° pitch:       [0, 0, +1]  ✓

Voraussetzung: Gazebo IMU muss msg.orientation publishen.

7. SMOOTH POLICY RUNNER — RUCKELIGKEIT IN ROS2
--------------------------------------------------------------------------------

Ursache der Ruckeligkeit: Policy-Output bis ±40 wird auf ±1 geclippt
→ Gelenkziele springen ±0.5 rad / 0.02s = 25 rad/s (Limit: 0.8 rad/s)

Lösung: SmoothPolicyRunner in export_policy_ros2.py
  EMA-Smoothing:    smooth = α*raw + (1-α)*smooth_prev  (α=0.20)
  Rate-Limiting:    delta = clamp(smooth - prev_sent, ±max_delta)
  max_action_delta = 0.032 → max 0.8 rad/s Gelenkgeschwindigkeit (= HW-Limit)

Ergebnis: Worst-case 25 rad/s → max 0.8 rad/s, kein Ruckeln mehr.
